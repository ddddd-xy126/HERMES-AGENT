# Hermes × BrowserHarness 集成方案 — 保姆级部署与运维手册

> **文档目标**：把这套"飞书 → 爱马仕 LLM Agent → 自动化 Chrome → 内部 Web 系统（51pm 等）"的整合方案讲清楚。**任何小白照本宣科都能从零跑起来；扔给另一个 AI 也能按步骤逐一部署**。
>
> **适用版本**：Hermes Agent **v0.11.0** (2026.4.23) · BrowserHarness **v0.1.0** · Windows 11 + WSL2 (Ubuntu) + Chrome 自动化 profile

---

## 0. 5 分钟看懂这套东西做什么

> **一句话**：你在飞书里 @ 爱马仕，它就能像同事一样登录你的内部网站（51pm 项目管理、未来还能加 OA、Jira 等）按步骤完成查询、汇报、操作；并能定时主动推送（每天早上 8:40 自动播报本周任务）。

**最小可演示场景（已落地 ✅）**

| 输入 | 行为 | 输出 |
|---|---|---|
| 飞书 DM："本周组员任务" | Agent 拉起 Chrome → 登录 51pm 测试环境 → 切「项目任务」+「非项目任务」两 tab → 读列表 | 任务清单 + 询问"全部完工 / 按编号 / 跳过" |
| 用户回 `P-01,P-03` | Agent 逐行点 `button.finish` 按钮 | 完工反馈截图 |
| 每天 08:40（无需触发） | cron 主动跑上面的查询并推到 DM | 早报消息 + AskUserQuestion |

                                       ▼
                          ┌────────────────────────────────┐

### 1.2 关键设计决策

| 决策 | 原因 |
|---|---|
| **WSL 跑 Hermes，Windows 跑 Chrome** | Hermes 是 Linux-friendly 的 Python 包；用户日常 Chrome / 内部网必须留在 Windows，避免冲突 |
| **9333 + 独立 profile** | 你日常 Chrome 默认 9222，避免端口/Cookie/扩展冲突；automation-profile 独立可清理重置 |
| **portproxy v4tov6** | Windows 上的 Chrome `--remote-debugging-address=0.0.0.0` 实际只绑 `[::1]:9333`（IPv6），WSL 默认走 IPv4 网络拿不到，所以必须做 IPv4↔IPv6 桥接 |
| **domain-skills 单源 + 软链** | 你只在 `D:\...\BrowserHarness\agent-workspace\domain-skills\` 改；WSL 通过 symlink 直接读，无需双向同步 |
| **`USER.md` 全局规则** | Hermes 每条消息都把 `~/.hermes/memories/USER.md` 注入 system prompt，比 per-skill 指令更稳，绕开"加载子 skill 时丢失父 skill 指令"的问题 |
| **`_ensure-chrome.sh` 自愈** | Chrome 挂了 / 关机重启后，Agent 一看到 `BU_CDP_URL unreachable` 就自动 `powershell.exe` 拉起，不打扰用户 |

## 2. 技术栈

### 2.1 上层

| 组件 | 版本 | 角色 |
|---|---|---|
| **Hermes Agent** | v0.11.0 | LLM Agent 框架；提供 IM 网关（飞书/钉钉/Telegram...）、skill / memory / cron / hook / mcp 系统 |
| LLM | claude-opus-4-7 | 通过 N1nKey 网关 (`https://api.n1n.ai/v1`) 调用 |
| **BrowserHarness** | v0.1.0 | 一个 Python CLI + 守护进程，把 Playwright/CDP 的浏览器操作抽成 `goto_url() / click_at_xy() / page_info() / type_text()...` 等 helper，给 LLM 调 |

### 2.2 运行时

- **WSL2** Ubuntu（你机器是默认发行版）
- **Python 3.11.15** (Hermes / BrowserHarness 共用)
- **Chrome / Chromium**（Windows 侧，CDP 模式）
- **`uv`**（Astral 的 Python 包管理器，安装 BrowserHarness 时用）
- **`netsh interface portproxy`**（Windows 自带，端口转发）

### 2.3 通信协议

| 链路 | 协议 |
|---|---|
| 飞书 ↔ Hermes gateway | 飞书 Webhook + 长连接事件 |
| Hermes gateway ↔ LLM | OpenAI 兼容 HTTP（N1nKey 转发到 Anthropic） |
| Hermes ↔ BrowserHarness | subprocess + `/tmp/bu-hermes.sock` (UNIX domain socket) + 环境变量 |
| BrowserHarness ↔ Chrome | CDP over HTTP/WebSocket (`/json/version`, `/devtools/page/...`) |

## 4. 从零部署（保姆步骤）

> 假设：一台干净 Windows 11 + WSL2 Ubuntu 已装好。**所有命令复制粘贴即可**。

### 4.1 准备（一次性，5 分钟）

#### Windows 侧

```powershell
# 1. 装 Chrome（如果没装），并准备一个独立 profile 路径
mkdir "$env:LOCALAPPDATA\BrowserHarness\automation-profile" -Force

# 2. 以管理员开 PowerShell，执行 portproxy + 防火墙规则（只跑一次）
cd D:\project\hermes-agent\AgentGroups\harmesAgent
.\_start-automation-chrome.ps1
```

> ⚠️ `_start-automation-chrome.ps1` 的 portproxy 行必须是 **`v4tov6` + `connectaddress=::1`**。如果脚本里写的是 v4tov4，按下面手动跑一次：
>
> ```powershell
> netsh interface portproxy add v4tov6 listenport=9333 listenaddress=0.0.0.0 connectport=9333 connectaddress=::1
> netsh advfirewall firewall add rule name="BrowserHarness 9333" dir=in action=allow protocol=TCP localport=9333
> ```

验证：
```powershell
netsh interface portproxy show v4tov6   # 应看到 9333 → ::1:9333
```

#### WSL Ubuntu 侧

```bash
# 1. 装 uv（如果没有）
curl -LsSf https://astral.sh/uv/install.sh | sh
source ~/.bashrc

# 2. 装 Hermes
bash /mnt/d/project/hermes-agent/AgentGroups/harmesAgent/install-hermes.sh

# 3. 跑配置向导（首次需要）
hermes setup
```

`hermes setup` 会问你 LLM 提供商、API key、飞书 app_id/secret 等。配置写到 `~/.hermes/config.yaml` 和 `~/.hermes/.env`。

### 4.2 接入飞书（5 分钟）

1. 飞书开放平台创建企业自建应用（bot）。记下 4 个值：`app_id`、`app_secret`、`encrypt_key`（可为空）、`verification_token`
2. 应用能力 → 勾选《机器人》。事件订阅 → 勾选 `im.message.receive_v1`。现代事件推送 → 选 `WebSocket`（推荐，免公网）或 HTTP 回调
3. 仓库里拷贝配置模板：

   ```bash
   cp /mnt/d/project/hermes-agent/AgentGroups/harmesAgent/config/config.template.yaml ~/.hermes/config.yaml
   cp /mnt/d/project/hermes-agent/AgentGroups/harmesAgent/config/env.template ~/.hermes/.env
   ```

   然后用你喜欢的编辑器（或下面脚本）填上 `app_id / app_secret / encrypt_key / verification_token / OPENAI_API_KEY`。

   不想手填：`hermes setup` 可以交互式引导，但不适合交给 AI 复制制。**服务化、可复制的部署走模板路**。
4. 启动 gateway：
   ```bash
   bash /mnt/d/project/hermes-agent/AgentGroups/harmesAgent/scripts/runtime/start-gateway.sh
   ```
5. 飞书 DM 里 @ 机器人发“你好”，能回话即成功。**第一次对话会自动入库到 `~/.hermes/channel_directory.json`**（DM 的 `oc_xxx`）——这是后面配 cron deliver 要用的 ID。

### 4.3 接入 BrowserHarness（10 分钟）

```bash
cd /mnt/d/project/hermes-agent/AgentGroups/harmesAgent

# 1. clone + 安装到 WSL 原生路径（注意：不能放 /mnt/d，egg-info 写不了）
bash _install-browser-harness.sh

# 2. 把 D:\ 下的 domain-skills 软链进 WSL 工作区（单源）
bash _link-windows-workspace.sh

# 3. 写 BU_CDP_URL=http://<WSL host>:9333 到 ~/.hermes/.env，重启 gateway
bash _wire-browser-harness.sh

# 4. 放开 Hermes 安全策略：把 browser-harness / _ensure-chrome.sh 加 allowlist，关 Tirith
bash _allow-browser-harness.sh

# 5. 生成 ~/.hermes/skills/browser-harness/SKILL.md（含所有 domain-skills 索引）+ 重启
bash _sync-skills.sh

# 6. 自检
bash _ensure-chrome.sh           # 看到 ✓ Chrome reachable
bash _test-browser-harness.sh    # 看到 {url: about:blank, ...}
```

### 4.4 注入全局规则（关键）

`~/.hermes/memories/USER.md` 每条消息都被注入 system prompt。把 Chrome 自愈和"禁止让用户跑 PowerShell"写进去：

```bash
cp /mnt/d/project/hermes-agent/AgentGroups/harmesAgent/prompts/memory-rule.md /tmp/rule.md
# 保留 USER.md 第一行的用户基本信息，再追加规则
head -1 ~/.hermes/memories/USER.md > /tmp/u.md
cat /tmp/rule.md >> /tmp/u.md
mv /tmp/u.md ~/.hermes/memories/USER.md
cat ~/.hermes/memories/USER.md   # 检查
```

> 已有内容请别盲目覆盖。看一眼现有 `USER.md` 第一行，再决定是 append 还是手 merge。

### 4.6 首次手动登录内部站点（必须）

**这一步不能跳**。automation Chrome 是独立 profile，里面什么帐号都没。

```powershell
# Windows 跱 _launch-automation-chrome.ps1 拉起 Chrome
.\_launch-automation-chrome.ps1
```

在这个 Chrome 里手动访问 `http://10.67.8.183:7777` → 走企业微信 OAuth 扫码登录一次，Cookie / Session 会被 profile 记住。以后 Agent 拉起 Chrome 就是登录态。

同理，以后接任何新站点（Jira / OA / GitHub Enterprise…）都需要首次手动登一下。**永远不要让 Agent 帮你输密码**。

## 5. 配置详解

### 5.1 `~/.hermes/.env`

```ini
OPENAI_BASE_URL=https://api.n1n.ai/v1
OPENAI_API_KEY=<your-key>
LLM_MODEL=claude-opus-4-7

FEISHU_ALLOWED_USERS=                          # 留空=所有用户都能用，否则用 open_id 列表
FEISHU_GROUP_POLICY=open                       # open/closed

BU_CDP_URL=http://172.27.192.1:9333            # WSL 看到的 Windows 主机 IP
BU_NAME=hermes                                 # BrowserHarness daemon socket 后缀
BH_AGENT_WORKSPACE=/home/huazhonghao/Developer/browser-harness/agent-workspace
```

> **`172.27.192.1` 不是固定的**！每台机器不同。WSL 启动脚本会从 `ip route default` 自动检测，已写在 `_wire-browser-harness.sh` 里。

### 5.2 `~/.hermes/config.yaml` 关键段

```yaml
gateways:
  feishu:
    enabled: true
    app_id: cli_a97a3c2fc3f99bc9
    app_secret: <secret>
    # ...

security:
  allow_private_urls: true                     # 允许访问 10.x / 172.x 等内网（Tirith off 后冗余但建议保留）
  tirith_enabled: false                        # 关掉私网/危险 URL 拦截器
  command_allowlist:                           # 允许直接 subprocess 不弹审批卡
    - browser-harness *
    - browser-harness
    - bash /mnt/d/project/hermes-agent/AgentGroups/harmesAgent/scripts/runtime/ensure-chrome.sh
    - bash /mnt/d/project/hermes-agent/AgentGroups/harmesAgent/*.sh
    - bash /mnt/d/project/hermes-agent/AgentGroups/harmesAgent/scripts/**/*.sh
```

> 想改 allowlist 直接编辑 yaml；或者跑 `_patch-allowlist.py`。

每条用户消息处理时被读取并拼到 system prompt 顶部。**适合放绝对硬规则、用户身份、域名映射**。

## 7. 日常运维 Playbook

### 7.1 加 / 改 skill（最常见）

> **单源原则**：你只在 `D:\project\hermes-agent\AgentGroups\BrowserHarness\agent-workspace\domain-skills\` 改文件。

| 场景 | 要不要 sync？ |
|---|---|
| 编辑现有 .md 内容 | **不用**。WSL 是 symlink，文件改完 Agent 下次读就是新的 |
| 新增 / 删除 .md 或子目录 | **要**：跑 `bash _sync-skills.sh`（重生成 SKILL.md 索引并重启 gateway） |
| 改了 .md 的 H1 标题 | **要**：sync（H1 进了索引） |
| 改了 USER.md / config.yaml | 重启 gateway：`bash _restart-gateway.sh` |

### 7.2 Chrome 没起来 / 连不上

```bash
bash /mnt/d/project/hermes-agent/AgentGroups/harmesAgent/scripts/runtime/ensure-chrome.sh
```

返回 `✓ Chrome reachable` 即恢复。Agent 现在应该自己干这事，不需要人工介入。

如果连 ensure 也失败：
1. Windows 上 `netsh interface portproxy show v4tov6` 看 9333 是否在
2. Windows 上手跑 `_launch-automation-chrome.ps1`，看 `http://127.0.0.1:9333/json/version` 通不通
3. WSL 里 `curl http://$(ip route default | awk '{print $3}'):9333/json/version`

### 7.3 cron 管理

```bash
# 看所有定时任务
~/.local/bin/hermes cron list

# 立即试跑（不等到下个时间点）
~/.local/bin/hermes cron run <job-id>

# 暂停 / 恢复
~/.local/bin/hermes cron pause <job-id>
~/.local/bin/hermes cron resume <job-id>

# 删除
~/.local/bin/hermes cron rm <job-id>
```

改 prompt 后重装：

## 8. 常见坑 & 排错

| 症状 | 根因 | 修法 |
|---|---|---|
| Agent 让用户手动跑 PowerShell 拉 Chrome | USER.md 没装 / 内容乱码 | 重新写 USER.md（4.4 节），关键词："绝对禁止" |
| Agent 弹"Command Approval"卡 | allowlist 没含命令 / Tirith 开着 | `bash _allow-browser-harness.sh` |
| `BU_CDP_URL ... unreachable` 但 Chrome 显然在跑 | portproxy 用了 v4tov4，9333 实际只在 IPv6 | 改成 v4tov6（4.1 节注释） |
| `pip install` BrowserHarness 报 egg-info 失败 | 装到了 `/mnt/d/...`（NTFS 跨界） | 改装到 `~/Developer/`（WSL 原生 ext4） |
| Skill 加载后没看到 Chrome 自愈说明 | Hermes 自动选了子 skill（如 `51pm-task-ops`），父 skill SKILL.md 未加载 | 把规则放 USER.md（全局），不依赖 skill |
| 定时计划没触发 | `hermes cron tick` 不在跑 / gateway 没启 | `hermes cron status`、重启 gateway |
| 飞书消息回的延迟 / 漏 | network、LLM 网关排队 | 看 `~/.hermes/logs/gateway.log` || Windows 重启后 Chrome 拉不起 | portproxy 默认持久，但上次拉的 chrome.exe 进程死了 | `_ensure-chrome.sh` 会自动拉，手动也可跱 `_launch-automation-chrome.ps1`（这是仅有的合法人工介入场景） |
| WSL 重启后 BU_CDP_URL IP 失效 | WSL 重启后定义网段 IP 可能变（172.27.x.x） | `_wire-browser-harness.sh` 重跑，它会重新检测并写入 .env |
| 首次访问内部站点跳 OAuth | automation profile 里没登录过 | 人手动登一次（4.6 节） |
| Element UI 表格读重复行 | 固定列另渲染了一份 tbody | 只读 `.el-table__body-wrapper` 的主 body；skill 已记录 |
| 单元格 `textContent` 重复 | tooltip 副本 | dedupe：`s.length>1 && s.slice(0,h)===s.slice(h)` |
| Chrome 升级后疑似 profile 不兼容 | 路径 schema 变了 | 删了 `%LOCALAPPDATA%\BrowserHarness\automation-profile`重走 4.6 手动登录 |
| Hermes update 提示落后 200+ commit | 上游有快迭代 | `hermes update`，**升完跡一轮这份文档**，特别是 cron / skill / memory 接口 |

## 9. 增量维护工作流（人类 SOP）

> 这一节给你（人）看。下一节给 AI 看。

### 10.1 新增一个站点 skill（例：Jira）

1. 在单源下创建目录：`D:\project\hermes-agent\AgentGroups\BrowserHarness\agent-workspace\domain-skills\jira\`
2. 文件布局参考 51pm：
   - `README.md`——站点总述、环境、通用陷阱
   - `<动作名>.md`——一个动作一份。**读写分开**，写操作必须顶部有 `⚠️ 写操作 skill`、必须 `AskUserQuestion`
3. **首次**跱 `bash _sync-skills.sh`（重生成 SKILL.md 索引 + 重启）
4. 后续只改内容、不动文件名 / H1，不需要 sync
5. 首次访问该站点：手动走 4.6（OAuth/SSO 登录一次）

打个边鼓：只有可复现、可参数化的动作才值得写 skill。一次性查询直接跟 Agent 说、不要过度抽象。

### 10.2 修改现有 skill

- 只改内容：**什么都不用做**。WSL 是 symlink，下次 Agent 读到的就是新的。
- 改了 H1 / 重命名 / 增删文件：`bash _sync-skills.sh`。
- 加 / 改 frontmatter（`name:` `description:`）：sync。这决定 Hermes 怎么列出 skill 名。

### 10.3 加一个定时计划

1. 写一份独立的 prompt：`harmesAgent\_cron-prompt-<job>.md`，**必须是 self-contained**（说清楚干啥、怎么报）。
2. 写一行 install 脚本或复用 `_install-cron-daily.sh`（需要不同参数就 cp 一份改）。
3. 跱 install 脚本、记住 `Created job: <id>`。
4. 验证：`hermes cron run <id>` 试跑。错了就 `cron rm` 重来。
5. **注意**：prompt 修改后不会自动生效、必须 `cron rm` + 重装。

### 10.4 修改全局规则

写 / 改 `~/.hermes/memories/USER.md` 即可，每条消息现读、**不需重启**。但请保持简短（每条消息都要加载）。同理 SOUL.md（人格）、`config.yaml` 原则（安全 / 插件）。

人格设定调色 = SOUL.md；硬规则 / 身份信息 = USER.md；类型/宝塔型限制 = config.yaml。三者不要混。

### 10.5 状态检查 / 定期体检

每周建议跱一下：

```bash
~/.local/bin/hermes status                    # 看 gateway / cron / hooks
bash /mnt/d/.../harmesAgent/scripts/runtime/ensure-chrome.sh  # 看 Chrome
~/.local/bin/hermes cron list                  # 看定时计划
ls -la ~/.hermes/skills/browser-harness/SKILL.md  # 看 SKILL.md 是否过时
tail -50 ~/.hermes/logs/gateway.log | grep -iE 'error|exception' | tail
```

定期备份：`hermes backup ~/hermes-backup-$(date +%Y%m%d).zip`。**抓完拷一份到 `D:\` 上**，WSL 坏了还能恢复。

### 10.6 产品文档本身怎么跟进

出现以下事件时请同步修改本文档：

- Hermes / BrowserHarness 版本升级→ 顶部版本字样 + 末尾最后更新时间
- 添加新站点 skill → §6 表格
- 添加新 cron → §6.3 表格
- 改了部署脚本名 / 参数 → §3.1 目录布局
- 过去踩过一个坑且其它人也会踩 → §8 表格

## 10. 安全注意

- `~/.hermes/.env` 含 API key —— 别 commit、别贴聊天
- `tirith_enabled: false` 是为了让 Agent 能直连 `10.x` 内网 —— 这意味着 Agent 拥有你的内部访问能力，**飞书白名单（`FEISHU_ALLOWED_USERS`）务必收紧**
- automation-profile 里登录的 51pm session **就是 Agent 的"身份"**。它能做什么完全取决于你这个账号的权限。**不要给 Agent 用 admin 账号**
- skill 里凡是写操作（点完工、删除、提交）必须 `AskUserQuestion` 后再点击 —— `checkTask_confirmTask.md` 已是模板

[step 10] 设定时（把 oc_xxx 填进去）：
